# Direction Pose Expansion Plan

## 목표

현재 음악 시간 기반 원버튼 리듬 코어를 다음 형태로 발전시킨다.

> 중앙의 춤추는 불인간을 향해 괴상한 포즈의 나방인간들이 사방에서 접근한다. 플레이어는 나방의 이동 방향과 포즈를 읽고 같은 방향키를 박자에 맞춰 누른다. 콤보가 오를수록 불인간의 머리와 화력이 우스꽝스럽게 커진다.

## 핵심 플레이

1. 나방인간이 상·하·좌·우 중 한 방향에서 등장한다.
2. 나방인간은 요구 방향을 나타내는 고유한 포즈를 취한다.
3. 플레이어는 해당 방향키를 타이밍에 맞춰 누른다.
4. 입력 방향과 시간이 모두 맞으면 Perfect 또는 Good이다.
5. 방향이 틀리거나 노트를 놓치면 콤보가 초기화된다.
6. 콤보가 높아질수록 불인간의 머리와 화염 연출이 커진다.

## 확정 입력 규칙

| 등장 방향 | 입력 | 나방인간 포즈 | 핵심 실루엣 |
|---|---|---|---|
| 위 | `↑` | 상승숭배 | 팔과 날개가 위로 V |
| 아래 | `↓` | 지옥강림 | 양손과 더듬이가 아래를 지시 |
| 왼쪽 | `←` | 왼쪽 유혹 | S자 몸과 왼쪽으로 뻗은 팔 |
| 오른쪽 | `→` | 오른쪽 고발 | 오른쪽 삿대질과 활처럼 휜 몸 |

- 포즈는 과장된 관절, 연극적인 손동작, 비현실적인 균형을 사용한다.
- 네 포즈는 검은 실루엣만으로도 구분되어야 한다.
- 좌우 포즈를 단순 반전으로 만들지 않는다.
- 팔과 몸통이 주 신호이며 날개와 색은 보조 신호다.
- 이동 방향과 요구 입력 방향은 동일하게 유지한다.
- 첫 구현에서는 동시 노트와 복수 키 입력을 만들지 않는다.

## 판정 규칙

- 입력 방향을 `lane`으로 변환한다.
- 해당 `lane` 안에서 시간상 가장 가까운 노트만 찾는다.
- 방향과 시간이 모두 맞으면 Perfect 또는 Good으로 판정한다.
- 다른 방향의 노트는 해당 입력의 성공 후보가 될 수 없다.
- 시간은 맞지만 방향이 틀린 입력은 `Wrong Direction`으로 처리한다.
- 판정 가능한 노트가 없는 입력은 `Bad Tap`으로 처리한다.
- 노트를 놓치면 기존 자동 Miss를 적용한다.
- 키보드 입력은 IME와 자판 배열에 덜 흔들리도록 `physical_keycode`를 우선 사용한다.

### 첫 구현의 점수·체력 정책 (2026-07-26 개정)

벌칙을 콤보·체력이 아니라 **다음 판정의 상한**으로 준다. 방향을 틀려도 나방은 살아남고, 정확히 다시 칠 기회가 있다.

- Perfect와 Good의 기존 점수를 유지한다.
- 성공 시 콤보를 1 증가시킨다.
- **Bad Tap**(칠 노트가 아무 데도 없을 때의 입력)은 아무 벌칙이 없다. 콤보와 체력을 유지한다.
- **Wrong Direction**은 콤보와 체력을 건드리지 않는다. 대신 그 나방은 이후 Perfect를 받을 수 없고 Good이 상한이 된다. 나방은 제자리에 남아 다시 칠 수 있다.
- **정정 입력**이 성공하면 Good으로 처리하고 콤보를 1 증가시킨다.
- **자동 Miss**만 콤보를 0으로 초기화하고 체력을 1 감소시킨다.
- 방향 입력 전환 중에는 점수 배율을 추가하지 않는다.

> **미해결 위험 — 연타.** 틀린 입력에 대가가 없어 네 방향을 모두 누르면 매번 Good이 보장되고 콤보가 끊기지 않는다. 방향을 읽을 이유가 사라질 수 있다. 플레이 테스트로 확인하고, 문제면 Wrong Direction 직후 짧은 입력 잠금(0.1~0.2초)을 검토한다.

> 개정 전 규칙은 "Wrong Direction은 콤보를 0으로 초기화한다"였다.

## 불인간 표현

### 최소 애니메이션 상태

- `idle_dance`: 기본 반복 춤
- `perfect`: Perfect 성공 포즈
- `good`: Good 성공 포즈
- `damage`: Miss 반응
- `victory`: 승리
- `extinguish`: 패배

- 첫 구현은 `AnimatedSprite2D.play()` 중심으로 만든다.
- 판정 동작이 끝나면 `idle_dance`로 복귀한다.
- 복잡한 상태 머신은 현재 범위에 포함하지 않는다.

### 콤보에 따른 불대가리 성장

| 콤보 | 머리 크기 | 연출 단계 |
|---:|---:|---|
| 0–4 | 100% | 불씨 |
| 5–9 | 120% | 점화 |
| 10–19 | 150% | 화염 |
| 20–29 | 190% | 폭주 직전 |
| 30+ | 240% | 폭주 |

- 몸이 아니라 머리, 화염, 머리 주변광만 확대한다.
- 불인간 루트와 판정 위치는 움직이거나 확대하지 않는다.
- 콤보 증가 시 짧은 overshoot Tween으로 머리를 튕긴다.
- 새로운 단계에 진입할 때 더 강한 pulse를 한 번 재생한다.
- Miss 시 머리가 짧게 쪼그라든 뒤 기본 크기로 돌아간다.
- 최대 크기는 HUD와 접근 나방의 가독성을 해치지 않도록 실제 플레이로 조정한다.

권장 Scene 구조:

```text
FireMan
├── BodyVisual
├── HeadVisual
│   ├── FlameSprite
│   ├── FaceSprite
│   └── HeadLight
├── GroundLight
└── Shadow
```

## 나방인간 바리에이션

### 분리 원칙

- 이동 스타일과 외형 바리에이션을 분리한다.
- 이동 스타일은 기존 `Straight`, `Sine`, `Orbit`를 유지한다.
- 외형 바리에이션은 판정 시각, 이동 속도, 판정 범위를 변경하지 않는다.
- 모든 외형은 같은 `run`, `burn`, `fall` 동작 규칙을 공유한다.

### 첫 목표

- 방향 포즈 4종을 먼저 완성한다.
- 이후 색, 날개, 머리 실루엣이 다른 외형 3종을 추가한다.
- 이동 스타일과 외형은 독립적으로 조합할 수 있게 한다.
- 작은 화면에서도 포즈 방향이 외형 장식보다 먼저 읽혀야 한다.

## 실행 계획

### Phase 0 — 코드 점검과 기준선 확보

- [ ] 코드, Scene, ProjectSettings, export preset 전체 점검
- [ ] 즉시 수정 버그 / 방향키 전 구조 개선 / 제출 전 폴리싱으로 분류
- [ ] `Conductor` 음악 시간과 루프 누적 정확도 확인
- [ ] `Chart` 구간 전환 시 스폰 누락·중복 확인
- [ ] 게임 종료와 재시작 상태 확인
- [ ] HUD Tween 중복과 판정 표시 충돌 확인
- [ ] 코드 기본값과 Inspector export 값 비교
- [ ] Web 오디오 시작과 키보드 입력 조건 확인
- [ ] 가능하면 Godot headless 검사 수행
- [ ] 수동 회귀 테스트 기준 기록

완료 조건:

- 수정 우선순위와 근거 파일이 적힌 리뷰 결과가 있다.
- 방향키 기능을 추가하기 전에 고쳐야 할 blocker가 정리되어 있다.
- 현재 원버튼 버전의 정상 동작을 재현하는 테스트 목록이 있다.

### Phase 1 — 방향키 판정 세로 슬라이스

- [ ] 방향키 입력을 lane으로 변환
- [ ] lane별 가장 가까운 노트 탐색
- [ ] Perfect / Good / Wrong Direction / Bad Tap 분기
- [ ] 기존 자동 Miss, 점수, 콤보, 체력과 연결
- [ ] 한 번의 입력이 한 노트만 판정하도록 보장
- [ ] 임시 방향 표시로 네 방향을 수동 검증

완료 조건:

- 네 방향 입력이 각각 대응 lane만 판정한다.
- 올바른 방향으로 Perfect와 Good을 재현할 수 있다.
- 잘못된 방향이 성공으로 처리되지 않는다.
- 기존 체력, 승패, 결과 화면에 회귀가 없다.

### Phase 2 — 방향 포즈 나방인간

- [ ] 상승숭배 포즈 제작 및 연결
- [ ] 지옥강림 포즈 제작 및 연결
- [ ] 왼쪽 유혹 포즈 제작 및 연결
- [ ] 오른쪽 고발 포즈 제작 및 연결
- [ ] 방향 포즈별 `run`, `burn`, `fall` 확인
- [ ] 작은 화면과 흑백 실루엣 테스트

완료 조건:

- 텍스트나 색상 없이도 네 방향을 구분할 수 있다.
- 이동 중 포즈가 흔들려도 입력 신호가 유지된다.
- 성공과 Miss 연출 중 잘못된 방향 포즈가 나타나지 않는다.

### Phase 3 — 춤추는 불인간과 콤보 성장

- [ ] 실제 `idle_dance` 리소스 연결
- [ ] Perfect / Good / damage 애니메이션 연결
- [ ] victory / extinguish 연결
- [ ] `HeadVisual` 분리
- [ ] 콤보 단계별 머리 크기 적용
- [ ] 성장 overshoot와 Miss 축소 연출 적용
- [ ] 머리 크기가 판정점과 충돌 범위에 영향을 주지 않는지 확인

완료 조건:

- 불인간이 플레이 중 계속 춤춘다.
- 판정 결과에 맞는 동작 후 기본 춤으로 복귀한다.
- 콤보 단계가 올라갈수록 머리 크기가 명확히 증가한다.
- Miss 후 머리가 기본 크기로 돌아간다.
- 최대 크기에서도 노트와 HUD가 읽힌다.

### Phase 4 — 나방인간 외형 3종

- [ ] 외형 선택 데이터와 이동 스타일 분리
- [ ] 기본형 외형
- [ ] 날개 강조형 외형
- [ ] 머리 실루엣 강조형 외형
- [ ] 방향 포즈 4종과 외형 3종 조합 확인
- [ ] 외형에 따른 판정 차이가 없는지 확인

완료 조건:

- 최소 3종 외형이 무작위로 등장한다.
- 모든 외형이 네 방향 포즈와 조합된다.
- 어느 조합에서도 방향 가독성과 판정 타이밍이 유지된다.

### Phase 5 — 폴리싱과 제출

- [ ] 음악 싱크와 `manual_offset` 최종 조율
- [ ] Perfect / Good 판정 범위 조율
- [ ] 콤보 단계별 조명·불티·사이키델릭 강도 조절
- [ ] 디버그 메트로놈과 개발용 표시 배포 설정
- [ ] Web export
- [ ] 브라우저 오디오·방향키·재시작 QA
- [ ] 승리와 패배를 각각 끝까지 플레이
- [ ] 스크린샷 또는 GIF 제작
- [ ] 제출 페이지와 최종 빌드 준비

완료 조건:

- 처음 실행한 사람이 설명 없이 방향 입력 규칙을 이해한다.
- 음악과 노트 도착 타이밍이 체감상 일치한다.
- Web 빌드에서 오디오, 방향키, 재시작이 정상 작동한다.
- 디버그 요소가 제출 화면에 노출되지 않는다.

## 범위 제한

현재 계획에서는 다음을 만들지 않는다.

- 동시 노트
- 복수 키 조합
- 홀드 노트
- 방향 전환 노트
- 외형별 능력치
- 콤보 점수 배율
- 복잡한 애니메이션 상태 머신
- 실제 3D 전환
- 새로운 매니저 또는 전역 싱글턴
