# Core MVP Plan

> [!success] 완료 — 2026-07-25
> 단방향 이동, 클릭/Space 판정, Perfect/Good/Miss, 자동 Miss, 제거 후 반복 생성을 구현하고 플레이 검증했다.

## 개발 역할

- 사용자가 직접 Godot Editor와 GDScript로 구현한다.
- Claude Code는 구현자가 아니라 멘토 역할을 맡는다.
- Claude Code는 사용자의 명시적인 요청 없이 파일을 생성하거나 수정하지 않는다.
- Claude Code는 한 번에 하나의 작은 작업만 설명한다.
- 먼저 구현 목표와 필요한 Node/변수를 설명하고, 사용자가 직접 작성할 시간을 준다.
- 사용자가 작성한 코드나 Scene을 확인한 뒤 문제점과 다음 한 단계만 알려준다.
- 완성 코드를 통째로 제시하기보다 힌트, API 이름, 짧은 예시 순서로 돕는다.
- 사용자가 막혔다고 명확히 요청할 때만 필요한 최소 코드 조각을 제공한다.
- 리팩터링이나 범위 확장은 현재 작업의 완료 조건을 만족한 뒤에만 제안한다.

## 확정 테마

- 중앙 캐릭터: 불 머리 + 사람 픽토그램 몸의 댄서
- 접근 캐릭터: 나방 머리 + 사람 픽토그램 몸의 나방인간
- 접근 동작: 팔을 뒤로 뻗은 나루토 러닝
- 판정 동작: 중앙 캐릭터의 춤과 황당한 포즈로 나방인간을 코믹하게 태운다.
- Perfect는 완전 연소, Good은 불완전 연소 후 도주, Miss는 나방인간이 불 머리에 붙어 불꽃을 약하게 만드는 연출로 구분한다.
- 연소는 판정의 시각 피드백일 뿐이며 체력, 공격력, 데미지 시스템은 만들지 않는다.
- 상세 내용은 [[GDD#확정 콘셉트|GDD의 확정 콘셉트]]를 기준으로 한다.
- Core MVP 완료 후 최소 아트 3장으로 테마를 검증한다.
  - 중앙 캐릭터 기본 춤 포즈 1장
  - 나방인간 나루토 러닝 포즈 1장
  - Perfect 연소 포즈 1장

## 플레이 가능한 최소 루프

1. 착화점(HitPoint)이 화면에 고정되어 있다.
2. 빛 조각(Mote)이 한 방향의 생성 지점에서 착화점으로 이동한다.
3. 플레이어는 마우스 왼쪽 클릭 또는 `Space`를 한 번 누른다.
4. 착화점과 빛 조각 사이의 거리에 따라 `Perfect`, `Good`, `Miss` 중 하나를 판정한다.
5. 판정 결과를 우선 디버그 출력으로 확인한다.
6. 판정된 오브젝트는 제거한다.
7. 입력 없이 착화점을 지나 Miss 경계를 벗어나면 `Miss`로 처리하고 제거한다.
8. 새 오브젝트를 생성해 같은 루프를 반복할 수 있다.

## 구현 원칙

- 먼저 현재 Godot 프로젝트의 Scene과 Script 구조를 확인한다.
- 기존 구조가 쓸 수 있으면 유지하고, 이 계획을 위해 프로젝트를 전면 재구성하지 않는다.
- Godot 4.x의 Node, Scene, Signal 방식을 사용한다.
- 판정은 MVP에서 중앙(착화점)과의 월드 좌표 거리로 계산한다.
- 동시에 활성화되는 판정 대상은 하나로 제한한다.
- **사실 vs 해석 분리**: 빛 조각은 사실(착화점과의 거리 등)만 노출하고, Perfect/Good/Miss 해석은 판정자가 한다.
- **의존 방향**: 상위(Main)가 하위(빛 조각)를 생성·구독한다. 하위는 상위를 호출하지 않는다.
- 판정 수치는 `@export` 변수로 두어 Inspector에서 조정 가능하게 한다.
- 조작감 값(판정 거리, 이동 속도, 생성 간격)은 사람이 직접 플레이 확인하기 전에는 확정하지 않는다.
- 불필요한 매니저, 상태 머신, 전역 싱글턴, 리소스 계층은 만들지 않는다.
- 외부 에셋 없이 기본 도형으로 검증한다.
- 한 작업을 끝낸 뒤 헤드리스 실행으로 파서/런타임 에러를 확인하고 다음 작업으로 넘어간다.

## 최소 Scene / Script 책임

정확한 파일명은 기존 프로젝트 구조를 확인한 뒤 맞춘다. 기존 `main.tscn`을 재사용한다.

```text
main.tscn
├── Main (Node2D)          입력 감지 · 판정 · 생성 반복
├── SpawnPoint (Marker2D)  빛 조각 생성 위치
└── HitPoint (Marker2D)    고정 착화점(판정 기준)

Mote.tscn (신규, src/gameplay/)
└── Mote (Node2D)          착화점으로 이동 · 시각 표시 · 거리라는 사실 노출
```

### Main 책임

- 오브젝트 생성 (SpawnPoint → HitPoint 방향 주입)
- 클릭 또는 `Space` 입력 감지 (같은 한 행동)
- 현재 활성 오브젝트의 거리를 읽어 Perfect/Good/Miss로 해석
- 판정 결과 수신 및 출력
- 판정 완료 후 다음 오브젝트 생성

### Mote 책임

- 중앙 착화점을 향해 이동
- 착화점과의 현재 거리를 노출 (사실)
- 착화점을 지나 Miss 범위를 벗어났는지 노출
- `judged(result)` 대신 사실만 노출하고 해석은 Main이 담당
- 중복 판정 방지

## 판정 규칙

거리 조건은 겹치지 않게 가까운 범위부터 검사한다.

```text
거리 <= perfect_distance : Perfect
거리 <= good_distance    : Good
그 외 입력               : Miss
입력 없이 miss_distance를 지나침 : Miss
```

- 초기 수치는 임시값이며 플레이 테스트로 조정한다.
- `perfect_distance < good_distance < miss_distance` 관계를 유지한다.
- 오브젝트가 정확히 중앙에 도달하지 못하는 프레임 간 이동을 고려해 `move_toward` 또는 동등하게 안전한 이동 방식을 사용한다.

## 멘토링 기준으로 완료한 Core MVP 작업 순서

### 작업 0 — 기존 코어 제거

- `src/gameplay/cue.gd`, `cue.tscn`을 제거한다.
- `main.gd`를 이 계획 기준으로 재작성할 준비를 한다.
- 완료 조건: 프로젝트가 에러 없이 열린다.

### 작업 1 — 한 오브젝트 이동

- 생성 지점에서 중앙을 향해 이동하는 오브젝트 하나를 구현한다.
- 기본 도형으로 위치와 이동을 눈으로 확인할 수 있게 한다.
- 완료 조건: 실행 시 오브젝트가 한 방향에서 중앙으로 이동한다. Debugger 오류 없음.

### 작업 2 — 원버튼 판정

- 마우스 왼쪽 클릭과 `Space`를 같은 행동으로 처리한다.
- 거리 기반 Perfect / Good / Miss를 구현한다.
- 결과를 디버그 출력한다.
- 한 오브젝트가 두 번 판정되지 않게 한다.
- 완료 조건: 서로 다른 타이밍으로 세 결과를 모두 재현. 입력 한 번에 결과 한 번.

### 작업 3 — 자동 Miss와 반복

- 입력 없이 판정 지점을 지나면 Miss 처리한다.
- 판정된 오브젝트를 제거한다.
- 짧은 간격 뒤 다음 오브젝트를 생성해 루프를 반복한다.
- 완료 조건: 입력하지 않아도 Miss 후 다음 오브젝트 등장. 반복해도 고아 Node/중복 Signal 오류 없음.

### 작업 4 — 검증 및 보고

- Godot 헤드리스로 실행해 오류를 확인한다(AI 담당).
- Perfect / Good / Miss / 자동 Miss를 각각 사람이 플레이로 시험한다.
- 변경 파일, Inspector 조정값, 남은 문제를 보고한다.
- 이 계획 바깥의 기능은 추가하지 않는다.

## 다음 작업 — 점수와 콤보

- 상태는 현재 `Main`이 소유한다.
- Perfect는 100점과 콤보 +1, Good은 50점과 콤보 +1이다.
- Miss와 자동 Miss는 점수를 주지 않고 콤보를 0으로 초기화한다.
- 첫 구현에서는 콤보 점수 배율을 만들지 않는다.
- 최소 UI는 `Score`와 `Combo` Label 두 개만 사용한다.
- 판정 결과가 발생할 때만 UI를 갱신한다.
- 불화력 연출은 이번 작업에 포함하지 않되, 콤보 값을 이후 연출의 입력으로 재사용한다.
- 기존 이동, 판정 거리, 연소 시간, 생성 간격은 변경하지 않는다.
- 사용자가 직접 구현하고 Claude Code는 아래 완료 조건을 기준으로 한 단계씩 안내하고 리뷰한다.
